## 一、🔴 阻塞 GitHub 发布的（1 项）

### D1. 仓库许可证

**现状**：`package.json` 是 `"license": "UNLICENSED"`，且**没有 LICENSE 文件**。

**为什么必须定**：公开仓若无明确许可证，法律上默认「保留所有权利」——别人既不能用也不能改，这与「开源」的初衷直接矛盾。

**我的建议**（按你的实际意图三选一）：

| 选项 | 适用 | 说明 |
|------|------|------|
| **A. 私有仓保持 `UNLICENSED`** | 你只发私有仓 | 最省事。公开时随时补 |
| **B. 公开仓用 Apache-2.0** | 想真开源 | 与多数依赖兼容，**明确授予专利授权**（医疗软件常涉及专利，Apache-2.0 的专利条款是加分项） |
| **C. 公开仓用 MIT** | 想最大程度宽松 | 最短最宽松，但**无专利条款**，对医疗项目略薄 |

**我推荐 B**（Apache-2.0）。理由：本项目依赖 dcm4chee（MPL-2.0）与 Cornerstone（MIT），Apache-2.0 与它们兼容；且 Apache-2.0 的专利授权条款对医疗软件有实际价值。

**注意**：这个决定只影响公开的「方法论仓」。**交付给院方的私有仓建议始终保持 `UNLICENSED`**——它含院方定制内容与商业信息。

## 二、🔴 阻塞 AI 模块的（1 项）

### D2. 院方 GPU 现状

**现状**：未知。

**已量化的要求**（ADR-007 + 架构师实测）：

| 项 | 要求 |
|---|---|
| GPU 显存 | **≥12GB**（RTX 3090 / A10 级） |
| TotalSegmentator 显存占用 | 8–12GB，且需独占调度 |
| 常规模型推理耗时 | 2–3 分钟（`--fast` 1–2 分钟） |
| P0 承诺时限 | 10 分钟 |

**两种情形**：

- **有 ≥12GB 显存的 GPU** → AI-01 按 P0 实现，无降级
- **只有 CPU** → 10 分钟时限**不成立**，AI-01 须降级为 P1，或换轻量模型

**这一项直接决定 AI 分割模块是否进本期**。

## 七、🟡 GitHub 发布形态（1 项）

### D10. 公开仓放什么

**我的建议（ADR-009）**：分两仓。

| 仓库 | 可见性 | 内容 |
|------|--------|------|
| `medplan` | **private** | 全部：完整 openapi / schema / UIUX / ADR / 部署配置 |
| `medplan-compliance-patterns` | **public** | 脱敏后的合规实现层：审计表 DDL + hash chain 触发器 + 不可区分越权响应 + AI 边界编译期断言 + 门禁脚本 |

**公开仓不含**：PACS 对接、AI 编排、部署编排、院方定制内容。

**理由**：PRD 里院方信息科的原话是「最担心引入新系统增加攻击面」。把防护逻辑全部公开，等于把攻击面说明书一并交出。

**若你坚持单仓公开**，请告诉我——我会先跑一遍 `npm run lint:publish`（14 条脱敏断言，已全部通过），并额外做一次人工复核。
