# ADR-003: 分割引擎采用 TotalSegmentator 2.18.0 + 自建服务层，不引入 MONAI Deploy

## Status: Accepted (2026-10-22)

## Background

PRD AI-01 要求提交预处理方案（肝胆/泌尿/胸外/全身）与目标期相，AI-02 要求返回器官/血管/病灶分段结果并支持三维重建。性能要求为腹部增强 CT 肝胆分割端到端 ≤10 分钟（含队列等待）。

同时，PRD AI-03 与 OOS-01/02 划定了不可逾越的边界：AI 只输出分割掩膜与量化指标，不产出诊断结论，不触及辅助决策类（依据《人工智能医疗器械注册审查指导原则》，国家药监局器审中心通告 2022 年第 8 号，该文件明确将「自动测量、自动分割、三维重建」列为**非辅助决策**类）。

候选：TotalSegmentator、MONAI Deploy、NVIDIA AI Enterprise、nnU-Net 裸训。

## Decision

采用 **TotalSegmentator 2.18.0**（发布于 2026-08-12），用**自建 FastAPI 服务层**封装。

不引入 MONAI Deploy。不采购 NVIDIA AI Enterprise。不自训 nnU-Net。

## Rationale

**1. MONAI Deploy 已实质停止维护**

联网核实：MONAI Deploy 最后一次提交为 **2025-03-26**，至今 18 个月无更新。作为临床生产编排框架，上游已停滞意味着引入即承担二开责任，且无人保障与新版 PyTorch/MONAI 的兼容性。

**2. NVIDIA AI Enterprise 成本与信创要求双重不匹配**

采购成本高，且绑定 NVIDIA 硬件生态，与等保三级的信创与国产化适配要求冲突。

**3. 我们不需要编排框架**

MONAI Deploy 的价值在多模型、多节点、复杂 DPApp 编排。本项目只有「提交任务 → 排队 → 推理 → 回调」的单链路。自建 FastAPI 包装约 1.5 人月，比适配 DPApp 约 2 人月更省且更可控。

**4. 许可证可满足，但需强约束**

TotalSegmentator 本身 Apache-2.0，但其 46 个 task 中存在两类限制，必须处理：
- **31 个 task** 标注为 `Openly available for any usage (Apache-2.0 license)`
- **14 个 task** 标注为需申请 license，非商业用途免费，商业用途需联系授权（含 `heartchambers_highres`、`appendicular_bones`、`tissue_types`、`coronary_arteries` 等）
- **1 个 task**（`brain_aneurysm`）为 CC BY-NC 4.0，**明确不提供商业许可**

强制约束（写入 AI 服务启动校验）：
- 仅允许 31 个 Apache-2.0 task 的白名单，其中包含 PRD AI-01 所需的 `total`、`total_mr`、`liver_segments`、`lung_vessels` 等，覆盖肝胆/泌尿/胸外/全身全部需求
- 非白名单 task 直接拒绝并记录审计（错误码 40003）
- 模型版本固定 2.18.0，与 PRD OOS-12「本期模型版本固定不更新」一致

**5. AI 合规边界在代码层强制**

AI 服务响应 schema 中**无任何自由文本字段**，只返回结构化 `structure_name` + `volume_ml` + DICOM SEG 引用。这使「AI 产出诊断结论」在类型层面不可能发生，而非依赖开发纪律。

## Consequences

### 正面

- 性能满足 P0 要求：RTX 3090 级 GPU 上常规模型 2–3 分钟，`--fast` 模式 1–2 分钟，10 分钟端到端有充足余量
- 显存需求 8–12GB，采购 RTX 3090 级（≥12GB）可满足
- 权重可离线预下载后随交付分发，院内环境无外网依赖
- 31 个 Apache-2.0 task 已覆盖本期全部需求，无需商业授权

### 负面

- 需自建服务层、任务队列、GPU worker 编排（约 1.5 人月）
- PyTorch 版本被上游锁死：`>=2.0.0, <2.6`，不能自由升级
- 分割质量依赖公开数据集训练，对罕见病例与特殊协议设备需实测验证
- 模型更新需走变更审批（OOS-12）

### 风险与缓解

- **GPU 依赖（R4）**：显存不足场景强制 `--fast` 并在报告标注降级；AI 不可用时阅片报告链路必须降级可用（PRD 可用性 P0 要求）
- **PyTorch 版本冲突（R10）**：镜像内锁定 2.5.x；CI 中执行真实推理 smoke test 作为构建门禁
- **许可证误用（R3）**：启动白名单校验 + 法务确认合同

## Alternatives Considered

| 方案 | 否决原因 |
|------|---------|
| MONAI Deploy express 0.6.1 | 上游 18 个月无更新，二开无人维护；编排能力对本项目过度设计 |
| NVIDIA AI Enterprise | 采购成本高；绑定 NVIDIA 硬件；信创适配差 |
| nnU-Net 2.8.1 裸训 | 需自建训练管线与模型资产，约 4 人月；无开箱权重 |
| 商业 AI 分割产品 | 私有化部署能力与信创适配需逐家验证；成本不可控 |
