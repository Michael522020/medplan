# ADR-002: 前端渲染自研 Cornerstone3D 5.13.1 封装，不 fork OHIF

## Status: Accepted (2026-10-22)

## Background

MedPlan 需要浏览器内的阅片工作台，支持 MPR 三视图、窗宽窗位、MIP/MinIP/VR 三种重建模式、测量工具、AI 分割结果的 labelmap 编辑。

候选路径有三：深度定制 OHIF、自研 Cornerstone3D 封装、或分发 3D Slicer 桌面端。

PRD 已排除桌面端（OOS-05：浏览器方案规避桌面端部署地狱）。

## Decision

采用**自研 Cornerstone3D 5.13.1 封装**（基于 OHIF 的模式，但不 fork OHIF 主干）。

不采用 OHIF 深度定制路线。

## Rationale

决策的转折点是一个通过联网核实发现的硬约束——**版本锁死**：

| 组合 | Cornerstone 版本 | 状态 |
|------|------|------|
| OHIF 3.13.13（最新稳定，2026-10-16 发布） | peerDependency 锁定 **5.6.8** | 生产可用 |
| OHIF 3.14.0-beta.60 | peerDependency 锁定 **5.12.0** | 预发布，不进生产 |
| Cornerstone3D 独立最新 | **5.13.1**（2026-10-16 发布） | 无 OHIF 约束时可用 |

采用 OHIF 就等于把 Cornerstone 锁在 5.6.8，落后上游 7 个 minor 版本。

四条理由：

**1. 版本锁死是架构性负债**

Cornerstone 5.x 有明确的破坏性变更节奏。锁在 5.6.8 意味着放弃上游后续的性能优化与 bug 修复，而这些修复会在项目 2 年生命周期内持续累积。跟随上游是长期正确选择。

**2. 需求与 OHIF 错配**

PRD 的核心差异化是「AI 分割 + 手术入路规划 + 结构化报告 + 医师签名」的闭环。OHIF 的价值集中在「通用阅片器」，与我们的差异化正交。用约 2 人月定制费获得一个通用阅片器，会把团队锁进 OHIF 的路由、状态、面板三重抽象，后续集成报告与签名需反复 hack 核心代码。

**3. 性能指标必须可控**

PRD 要求四项硬指标：2000 层首帧 3 秒、全量 15 秒、交互 30fps、三视图联动 200ms。这四项都需要在 `RenderingEngine` 与加载器层做针对性调优。OHIF 的默认行为为通用阅片设计，不保证这些指标；达标需要 hack 其内部加载策略，成本高于自研。

**4. SEG 手动编辑是硬需求**

PRD AI-02 要求合并、拆分、边界微调。Cornerstone 的 `@cornerstonejs/tools` 提供 labelmap 原语，自研可控；OHIF 的现成 SEG 编辑受其数据流约束。

## Consequences

### 正面

- Cornerstone 版本自由，可跟随上游
- 性能优化有完全控制权，可直接调 `RenderingEngine` 与加载器
- 应用层抽象干净，不被阅片器的路由/面板模型绑架
- 依赖树更小，供应链攻击面更小

### 负面

- SEG 编辑器、工具栏、快捷键体系需自研，多付约 1.5 人月
- 阅片器基础功能需自行验证，不能直接复用 OHIF 测试用例
- 需自行跟踪 Cornerstone 的破坏性变更

### 缓解与决策门

第 1 个月做性能验证原型（真实 2000 层数据）。若首帧 > 3 秒且无法优化，降级为「Cornerstone3D + 复用 OHIF 的 SegmentsReport/labelmap 工具子集」，保留此决策门。3 个月仍不达标则整体切换 OHIF 3.13.13 + Cornerstone 5.6.8。

此决策门写入架构方案 R1 风险项，不可省略。

## Alternatives Considered

| 方案 | 否决原因 |
|------|---------|
| OHIF 3.13.13 深度定制 | 锁死 Cornerstone 5.6.8，放弃上游 7 个 minor；性能达标需 hack 内部加载器 |
| OHIF 3.14 beta | 仍在 beta（最后发布 2026-10-21），预发布不进生产 |
| 3D Slicer 桌面端 | 与 OOS-05 冲突；逐台装机无 IT 管控，运维不可控 |
